# MIME Corpus

Hostile and broken MIME samples exercising the parser adapter (ADR 0002,
threat model §4.2) per `docs/testing-strategy.md` §2.

## Provenance

Every file in this corpus is **hand-crafted for this repository** from the
RFC examples and attack patterns described in the threat model; no real
correspondence is included. Regression fixtures from fuzz crashes are added
as `regression-<issue>.eml` in the appropriate group.

## Groups

| Group | Cases |
|-------|-------|
| `broken-headers/` | missing semicolons, un-escaped folds, 8-bit in headers, truncated encoded-words, no-colon lines |
| `rfc2047/` | mixed encodings, unknown charsets, split/continuation words, empty and broken tokens |
| `charsets/` | ISO-8859-1, Windows-1252, Shift-JIS, GB2312, invalid UTF-8 byte sequences |
| `nesting/` | valid multipart nesting (depth 3 and 63); the >64 limit case is generated by the test |
| `bombs/` | transfer-encoding expansion cases (bounded; the 100× ratio and size caps are asserted in tests) |
| `ambiguous/` | duplicate headers, conflicting content types, missing boundary close, LF-only endings |

## Expected outcomes

The corpus loader (`kestrel_core::testkit::load_mime_corpus`) feeds the
parser; the corpus test asserts the **class** of outcome deterministically:

- everything must parse without panicking;
- charset cases must produce the correct transcoded text;
- no file may exceed the threat-model §4.2 limits (these files are all
  well under the caps; limit enforcement is tested with generated input).
