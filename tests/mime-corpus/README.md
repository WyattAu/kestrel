# MIME Corpus

Hostile and broken MIME samples exercising the parser adapter (ADR 0002,
threat model §4.2) per `docs/testing-strategy.md` §2.

## Provenance

Every file in this corpus is **hand-crafted for this repository** from the
RFC examples and attack patterns described in the threat model; no real
correspondence is included. Regression fixtures from fuzz crashes are added
as `regression-<issue>.eml` in the appropriate group. The deep-`rfc822`
stack-overflow regression (issue #14) is covered by an in-memory generated
chain in `crates/kestrel-core/tests/mime_corpus.rs`
(`regression_14_deep_rfc822_chain_hits_depth_cap_not_stack_overflow`)

## Groups

| Group | Cases |
|-------|-------|
| `broken-headers/` | missing semicolons, un-escaped folds, 8-bit in headers, truncated encoded-words, no-colon lines, NUL bytes in folds, lone-CR line breaks, glued header values (`Subject:Re:...`), folds running to EOF |
| `rfc2047/` | mixed encodings, unknown charsets, split/continuation words, empty and broken tokens, unterminated encoded-words, adjacent words with mixed charsets, encoded display names |
| `charsets/` | ISO-8859-1, ISO-8859-15, Windows-1252, Shift-JIS, GB2312, UTF-16LE, invalid UTF-8, unknown declared charsets, hostile charset parameter quoting |
| `nesting/` | valid multipart nesting (depth 3, 63, and 64 — the documented cap); `message/rfc822` chains (3-level forward, 63 shells valid, 80 over cap); the >64 multipart limit case is generated by the test |
| `bombs/` | transfer-encoding expansion cases (bounded; the 100× ratio and size caps are asserted in tests); a zlib payload that must stay inert (never inflated) at the parser boundary |
| `related/` | `multipart/related` with a `cid:`-referenced inline image (parts stay resolvable) and a broken-root variant that must remain listable |
| `ambiguous/` | duplicate headers, conflicting content types, missing boundary close, LF-only endings, `text/html` before `text/plain` in `multipart/alternative`, absent Content-Type |

## Expected outcomes

The corpus loader (`kestrel_core::testkit::load_mime_corpus`) feeds the
parser; the corpus test asserts the **class** of outcome deterministically:

- everything must parse without panicking;
- charset cases must produce the correct transcoded text;
- no file may exceed the threat-model §4.2 limits (these files are all
  well under the caps; limit enforcement is tested with generated input).
